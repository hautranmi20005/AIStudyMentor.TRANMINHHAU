# Exact-match AI response cache

The AI response cache is exact-match after canonicalization; it does not use embeddings or semantic similarity. Cache keys are SHA-256 digests of canonical JSON containing normalized question text, subject, education level, explanation style, age group, answer language, task type, prompt version, model ID, image MIME type, image-content SHA-256, and quiz question count where applicable. Keys are namespaced by environment and cache schema (`studymentor:ai:<environment>:v1:<digest>`). Programming questions preserve case because identifier casing can change meaning; other questions are case-folded after NFC normalization, whitespace collapsing, and trimming.

Prompt version and model ID are in the key. Bumping either makes prior entries unreachable; they expire by TTL rather than requiring a Redis-wide flush. Cache TTL defaults to seven days with up to 10% positive jitter and is configurable through `AI_CACHE_TTL`. The environment namespace is configurable through `AI_CACHE_ENVIRONMENT`.

Only a validated, sanitized, output-safety-checked structured response is cached. Cache values contain response fields only, without profile/user identifiers, per-user remaining quota, token usage, or question ownership. Each answer request still creates its own question and answer rows in MySQL; each quiz request persists a new quiz and its own questions. The AI usage record marks `cache_hit=true` and zero input/output tokens on hits.

The authenticated API rate-limit filter runs before orchestration and applies even to cache hits. The daily AI call/token quota is reserved only after an exact cache miss; a cache hit consumes no daily AI quota. Concurrent identical misses in one application process are coalesced with single-flight; followers wait for the in-flight provider result. Redis cache errors bypass the cache, warn without logging question/key data, and continue to the provider. If Redis quota operations fail, a process-local daily quota fallback is used; its counters are not shared across replicas and reset on process restart.

`/actuator/ai-cost` is available only through the management listener and its existing monitoring-role authentication. `scripts/ai-cost-report.ps1` prints process-local provider-call/cache counters, hit rate, estimated saved tokens, and estimated costs. Cost price assumptions are configurable with `AI_COST_INPUT_USD_PER_MILLION` and `AI_COST_OUTPUT_USD_PER_MILLION`. Metrics reset when the application restarts; estimated saved tokens/cost extrapolate average observed provider token usage and are not billing data.
