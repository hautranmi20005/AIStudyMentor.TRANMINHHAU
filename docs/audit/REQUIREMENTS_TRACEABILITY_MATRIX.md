# Requirements Traceability Matrix

## Basis and labels

The available authoritative requirement list is [`Core/SRS.md`](../../Core/SRS.md), which defines FR-01A..FR-01D and FR-02..FR-08 plus NFR-01..NFR-05. It does not define FR-09..FR-11. The Product Completion Blueprint and Technical SPEC v2 named in the task are absent; no requirements are invented for the missing IDs.

Statuses use exactly these labels: **Implemented and verified | Implemented but not verified | Partially implemented | Documented only | Not implemented | Blocked / decision required**. After correcting local datasource/Redis environment overrides, P19 verified backend Actuator health and APK installation/launch. No authenticated end-to-end requirement is labelled “Implemented and verified.”

## P19 cross-cutting verification

- JDK 17.0.21 was selected. Backend `package -DskipTests` passed; P19 Maven `verify` was interrupted during the integration suite. Nine fresh XML reports contain 29 completed tests with no failures/errors/skips, but the full suite has no final status; see [partial evidence](../evidence/final/backend/MAVEN-VERIFY-STATUS.md).
- P19 Android XML reports show 18 unit and 18 connected tests passed, with 0 failures, errors, or skips in each. `lintDebug` completed with 0 `HardcodedText` findings.
- MySQL, Redis, Mailpit, and `emulator-5554` were healthy. The initial startup failure was traced to mismatched local datasource/Redis settings; after correction, the demo bootstrap completed and authenticated Actuator health returned `UP`. No database volumes were reset.
